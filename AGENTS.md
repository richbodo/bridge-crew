# Bridge Crew — notes for coding agents

A real-time planning room for two humans and a crew of AI agents, built as a research
instrument. Read [docs/plans/BRIDGE_CREW_PLAN.md](docs/plans/BRIDGE_CREW_PLAN.md) for the design
and build phases. The predictions in
[docs/research/BRIDGE_CREW_RESEARCH_BRIEF.md](docs/research/BRIDGE_CREW_RESEARCH_BRIEF.md) are
frozen: append corrections, never edit them.

## Stack

- **App:** TanStack Start (React 19, Vite 8, SSR). File-based routes in `src/routes/` (see its
  README). Server code is `createServerFn` in `src/lib/*.functions.ts`; modules named
  `*.server.ts` are server-only and must never be imported from client code.
- **Data:** Supabase — Postgres with row-level security, Auth (email + password), Realtime.
  Runs locally through the Supabase CLI. The schema is `supabase/migrations/`; add a new
  migration for every change, never edit one that has been applied, then run `bun run db:types`.
- **Crew model calls:** `src/lib/model.server.ts` — the Anthropic API, or canned `fixture`
  replies for tests. No local models.
- **UI:** Tailwind 4 + shadcn/ui. `src/components/ui/` is managed by the shadcn CLI.
- **Packages:** Bun (`bun.lock`). `bunfig.toml` blocks versions published in the last 24 hours;
  don't add exclusions without asking.

## Commands

`just` is the front door (`just` alone lists every recipe); the recipes wrap the `bun run`
scripts and `scripts/*.sh`.

```
just infra                   # local Supabase + seeded users + .env (idempotent; infra-reset wipes)
just run                     # http://localhost:8080 (run-fixture: canned crew replies)
just demo                    # same, plus one-click demo logins, one sign-in per tab
just test                    # Vitest unit tests (src/**/__tests__)
just e2e                     # Playwright, own servers on :8181 and :8182 (demo), canned replies
just e2e-live                # Playwright with real Claude calls (costs credits)
just check                   # tsc + unit tests; `just lint` has a Prettier backlog
just build && just start     # production Node server from .output/
```

Setup, demo mode and troubleshooting: [docs/dev_setup.md](docs/dev_setup.md).

## Conventions

- Prefer the fixture provider in tests; only `e2e:live` should spend credits.
- `.env` is generated by `scripts/test-infra.sh`; personal settings and keys go in `.env.local`.
  Both are gitignored.
- Demo mode (`VITE_BRIDGE_CREW_DEMO=1`, `src/lib/demo.ts`) keeps each tab's Supabase session in
  `sessionStorage`. Anything that reads the session must go through the `supabase` client, never
  `localStorage` directly. The demo accounts are seeded by `scripts/test-infra.sh`.
- Generated files: `src/routeTree.gen.ts` (router plugin), `src/integrations/supabase/types.ts`
  (`bun run db:types`).
- `docs/users_guide.md` is the single source of truth for the users guide; the app links to it
  on GitHub. Keep it current when user-facing behavior changes.
- Two humans are first-class, and floor control is the novel part — see
  [docs/floor_state_control.md](docs/floor_state_control.md).
