# Bridge Crew — notes for coding agents

A real-time planning room for two humans and a crew of AI agents, built as a research
instrument. Read [docs/plans/BRIDGE_CREW_PLAN.md](docs/plans/BRIDGE_CREW_PLAN.md) for the design
and build phases. The predictions in
[docs/research/BRIDGE_CREW_RESEARCH_BRIEF.md](docs/research/BRIDGE_CREW_RESEARCH_BRIEF.md) are
frozen: append corrections, never edit them.

## Stack

- **App:** TanStack Start (React 19, Vite 8, SSR). File-based routes in `src/routes/` (see its
  README). Server code is `createServerFn` in `src/lib/*.functions.ts`; modules named
  `*.server.ts` are server-only and must never be imported from client code.
- **Data:** Supabase — Postgres with row-level security, Auth (email + password), Realtime.
  Runs locally through the Supabase CLI. The schema is `supabase/migrations/`; add a new
  migration for every change, never edit one that has been applied, then run `just db-types`.
- **Crew model calls:** `src/lib/model.server.ts` — the Anthropic API, or canned `fixture`
  replies for tests. No local models.
- **The Tester's playtest:** `src/lib/playtest.server.ts` plays the current version in
  Playwright's Chromium, headless (`playwright-core` is a runtime dependency, and the installer
  downloads the browser), with the game's clock paused between the Tester's turns. It launches
  full Chromium, which draws with the Mac's graphics chip, and falls back to the headless shell,
  which draws in software. Each step's game time runs in slices against a 15-second limit, so a
  slow game stops at the limit with a look while a stuck one restarts.
- **Games:** a version is a folder of files (`game_files`, stored by hash), run and shared as one
  file, its bundle (`src/lib/bundle.ts`). The **shelf** (`src/lib/shelf.ts`) is the libraries and
  fonts games may use: Three.js and fonts, built into `src/lib/vendor/` by `just shelf`. See
  [docs/plans/bigger-games-2026-11-16.md](docs/plans/bigger-games-2026-11-16.md). A game written
  as modules is built into one script by Rolldown, Vite's bundler (`src/lib/modules.server.ts`).
  The Engineer builds with tools on a copy of the current version: Anthropic's text editor,
  remove_file and try_game (`src/lib/build.ts`, `src/lib/build.server.ts`); the tool loop is
  `callModelWithTools` in `src/lib/model.server.ts`.
  Games open from GitHub links (`src/lib/github.server.ts`); tests use the fake repositories in
  `e2e/fixtures/github`. See
  [docs/plans/games-on-github-2026-11-16.md](docs/plans/games-on-github-2026-11-16.md).
- **UI:** Tailwind 4 + shadcn/ui. `src/components/ui/` is managed by the shadcn CLI.
- **Packages:** Bun (`bun.lock`). `bunfig.toml` blocks versions published in the last 24 hours;
  don't add exclusions without asking.

## Commands

`just` is the front door (`just` alone lists every recipe); the recipes wrap the `bun run`
scripts and `scripts/*.sh`.

```
just infra                   # local Supabase + seeded users + .env (idempotent; infra-reset wipes)
just run                     # http://localhost:8080 (run-fixture: canned crew replies)
just demo                    # same, plus one-click demo logins, one sign-in per tab, in a tab it opens
just test                    # Vitest unit tests (src/**/__tests__)
just e2e                     # Playwright, own servers on :8181 and :8182 (demo), canned replies
just e2e-live                # Playwright with real Claude calls (costs credits)
just check                   # tsc + unit tests; `just lint` has a Prettier backlog
just flows                   # the explorer: every 9-event path through docs/state_machines.md
just build && just start     # production Node server from .output/
```

Setup, demo mode and troubleshooting: [docs/dev_setup.md](docs/dev_setup.md).

## Conventions

- Prefer the fixture provider in tests; only `e2e:live` should spend credits.
- `.env` is generated by `scripts/test-infra.sh`; personal settings and keys go in `.env.local`.
  Both are gitignored. `.env`'s `SUPABASE_SECRET_KEY` bypasses row-level security, so only
  `src/lib/github-connect.server.ts` uses it, for the GitHub tokens that no sign-in may read.
  Everything else acts as the signed-in user.
- Demo mode (`VITE_BRIDGE_CREW_DEMO=1`, `src/lib/demo.ts`) keeps each tab's Supabase session in
  `sessionStorage`. Anything that reads the session must go through the `supabase` client, never
  `localStorage` directly. The demo accounts are seeded by `scripts/test-infra.sh`. Its lobby
  opens demo rooms by **Context** (`src/lib/demo-rooms.ts`); a context pack's opening scene is
  its `docs/context/<pack>/demo.md`, which the crew never reads.
- Generated files: `src/routeTree.gen.ts` (router plugin), `src/integrations/supabase/types.ts`
  (`just db-types`).
- Room templates (`src/lib/templates/`) set a room's roster, shared document, seats and rules.
  Job keys are text; look jobs up with `jobOf(template, key)`, never a fixed crew list. The
  Game Studio's rules for young people live in its `setting`; keep them there.
- **Tune the crew** ([plan](docs/plans/tune-the-crew-2026-11-19.md)) lets a computer change a
  job's duty, the Scribe's instructions and add crew-wide notes (`crew_tuning`,
  `src/lib/tuning.ts`). Runs read it through `applyTuning`, and a crew member's system prompt
  is built in `src/lib/instructions.ts`, which marks which parts are tunable; the setting and
  the formats the app parses stay locked. Each run keeps its prompt in `runs.instructions`.
- `docs/users_guide.md` is the single source of truth for the users guide; the app links to it
  on GitHub. Keep it current when user-facing behavior changes.
- Teachers don't use the command line. `scripts/install-mac.sh` (the one-line installer, run
  from `main` on GitHub) and `scripts/game-studio-mac.sh` (the Desktop shortcut) are their way
  in; keep them in step with the users guide's §1 and §5, and with the `just` recipes they call.
- Two humans are first-class, and floor control is the novel part — see
  [docs/floor_state_control.md](docs/floor_state_control.md). Every state in a room is drawn in
  [docs/state_machines.md](docs/state_machines.md): keep it in step with the code, in the same
  commit. Crew member moves go through the database functions in
  `supabase/migrations/20261103080000_crew_machines.sql`, never direct status writes.
